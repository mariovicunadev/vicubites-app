# CLAUDE.md

Guidance for Claude Code when working in this repository.

## Project

**Vicubites Ops**, an embedded Shopify app for **Vicubites**, a fictional premium dog and cat
food brand that sells **B2C** (pet owners, one-time and autoship) and **B2B** (veterinary
clinics, pet shops, groomers). Dev store: `vicubites.myshopify.com` (Plus plan). Built as a
custom app for that brand.

Modules:
- **Nutrition Data Health**: scores every product on the completeness of its nutrition data
  (guaranteed analysis, ingredients, feeding guide, image alt text, B2B catalog coverage) and
  fixes gaps in bulk.
- **Refill Radar**: predicts when each customer runs out of food (bag size × daily portion, or
  their real reorder cadence) and triggers reminders through Flow and Klaviyo.

Product copy describes nutrition only; no health or medical claims.

## Stack

React Router 7 app template · `@shopify/shopify-app-react-router` · Polaris web components +
App Bridge · Prisma (SQLite in development) · TypeScript `strict` · GraphQL codegen · Vitest.

Admin API version **2026-10**, pinned in `app/shopify.server.ts`, `.graphqlrc.ts` and
`shopify.app.toml`. Change all three together.

## Engineering workflow

1. **Spec-driven.** Every feature starts with a spec in `specs/NNN-name.md` (copy
   `specs/000-template.md`): goal, why it belongs in an app, acceptance criteria, estimate.
   No implementation without an approved spec.
2. **GitFlow.** `main` (released) and `develop` (integration); one `feature/NNN-name` branch per
   spec from `develop`; small commits; self-review the diff before opening a PR; merge only
   after approval.
3. **Current Shopify docs are the source of truth.** Use the Shopify AI Toolkit
   (`shopify-plugin:shopify` skill) to search the docs, and validate every Admin GraphQL
   operation (topic `admin`, `--version 2026-10`) before committing it.
4. **Least privilege.** Each spec adds only the access scopes it needs and lists them. For
   protected customer data, request only the fields a feature uses.
5. **Secrets.** Never display, print or read `.env` files, tokens or API secrets.
6. **Language.** Code, comments, commits, specs and docs in English.

## Conventions

- Admin API calls go through `adminGraphql()` (`app/lib/admin/graphql.server.ts`) with a
  `#graphql`-tagged `const` document, so codegen types the result and the variables. Mutations
  also call `assertNoUserErrors()`.
- Don't swallow a thrown `Response` from `authenticate.*` or `admin.graphql`: it's a
  re-authentication redirect.
- Business logic lives in pure functions under `app/lib/`, with unit tests next to them
  (`*.test.ts`). Routes stay thin: authenticate, call `app/lib`, render.
- Code that must never reach the browser lives in `*.server.ts` files.
- Run `npm run graphql-codegen` after changing any operation and commit `app/types/`.

## Useful commands

```bash
shopify app dev                     # local dev inside the admin (tunnel + hot reload)
npm run graphql-codegen             # regenerate Admin API types
npm run typecheck                   # React Router typegen + tsc
npm run lint
npm test                            # Vitest (npm run test:watch while developing)
npx prisma migrate dev              # after changing prisma/schema.prisma
shopify app config validate --json
shopify app deploy                  # release app config and extensions
```

## Repository layout

```
app/
├── lib/            # business logic and Admin API layer (pure, tested)
│   └── admin/      # adminGraphql(), AdminApiError
├── routes/         # React Router file routes (app.* = embedded admin pages)
├── types/          # generated by graphql-codegen (don't edit)
└── shopify.server.ts
prisma/             # schema and migrations (sessions + app data)
extensions/         # app extensions (theme, admin, checkout, Flow)
specs/              # feature specs
```
